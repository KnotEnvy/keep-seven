the contracts every module codes against, the asset pipeline, the rendering tiers and the
test harness. `CLAUDE.md` (pillars, budgets, team rules) and `docs/GDD.md` (design) rank
above it; `docs/ART_BIBLE.md` yields to this file and to `design/assets.json` on file

section 5 type-check under the strict settings of section 13 against three 0.186 and against

**Priorities.** Every asset and every clip carries `priority`:

- **0**: on the critical path and seen within 5 m, or load-bearing for a puzzle, a fight or
  the story (everything on GDD 20.1's "never cut" list; every asset on a numbered gate).
- **1**: on the path but not load-bearing: a placeholder is noticed and breaks nothing.
- **2**: dressing, secrets and polish clips (GDD 20.1 rows 1, 7, 11). A P2 clip names a

Rule for every art owner: **all of its P0 assets and clips are final (not placeholders)
before any P1 work starts, and all P1 before P2.** `node tools/asset-status.mjs` (foundation)
prints placeholders by owner and priority and exits non-zero with `--require=0` while any P0
is a placeholder; piece critics run it. A builder who runs out of time stops at a priority
boundary and says which one; nothing is half-built across it.

## 2. Stack decisions

- **No additional npm dependency is required.** Everything below uses what is installed.
- `package.json` (foundation edits it once, then it is frozen): set `"type": "module"`
  (Node 24 refuses `import` in `.ts` under a commonjs package and Vite warns), and add

  ```json
  "scripts": {
    "dev": "vite",
    "typecheck": "tsc --noEmit",
    "build": "tsc --noEmit && vite build",
    "test:unit": "vitest run",
    "test:e2e": "node --test tests/",
    "validate": "node tools/validate_layout.mjs && node tools/validate_assets.mjs",
    "assets": "node tools/build-assets.mjs"
  }
  ```
- `vite.config.mts`: `base: './'`, `publicDir: 'public'`, `server: { host: '127.0.0.1', port: 0, strictPort: true }`,
  `optimizeDeps: { noDiscovery: true, include: [] }` (two copies of three break `instanceof` and
  shader-chunk patches), `build: { target: 'es2022', assetsDir: 'js', assetsInlineLimit: 0 }`.
  The build has one input, `index.html`; sandbox pages are served by the dev server only.
- three addons are imported as `three/examples/jsm/<path>.js`, never `three/addons/`.
- WebGLRenderer only. The renderer's own `setEffects()`/`outputBufferType` path is not used
  (it does not mix with the `postprocessing` package). The context is created with
  `{ antialias: tier === 'min', depth: true, stencil: false, powerPreference: 'high-performance' }` (8.2).

## 3. Runtime architecture

### 3.1 Composition root (`src/main.ts`)

```ts
const ctx = createContext({ canvas, uiRoot, flags });      // core services + inert stubs in the six system slots
ctx.render  = createRenderSystem(ctx, canvas);             // order is free: a factory may not call another system
ctx.audio   = createAudioSystem(ctx);
ctx.player  = createPlayerSystem(ctx);
ctx.enemies = createEnemySystem(ctx);
ctx.world   = createWorldSystem(ctx);
ctx.ui      = createUiSystem(ctx, uiRoot);
const systems = orderSystems([ctx.player, ctx.enemies, ctx.world, ctx.render, ctx.audio, ctx.ui]);  // SYSTEM_ORDER
for (const s of systems) await s.init();                   // subscribe to events, build DOM, create renderer
await boot(ctx, systems);                                  // section 3.4: 'boot' -> 'title'
startLoop(ctx, systems);                                   // not started when flags.test
installDebugHook(ctx, systems);                            // flags.test || flags.dev
```

There are no module-level singletons. Anything a system needs from another it reaches
through `ctx` (typed by `GameContext`) or hears on `ctx.events`. A sandbox replaces any
system with a core stub (`src/core/stubs/`); that is the whole reason for the rule.

### 3.2 System lifecycle

| Call | When | Rules |
|---|---|---|
| factory `createXSystem(ctx)` | once | Construct only. No calls into other systems, no asset access, no DOM queries outside the element passed in. |
| `init()` | once, in `SYSTEM_ORDER`, awaited | Subscribe to events. Render installs the material resolver here, before any asset is activated. |
| `start()` | once, after the `always` set and the first resident set are active and `world.buildSet()` has run (boot calls it for the set of the start checkpoint) | Create pools, instantiate assets, warm up. May be async. |
| `fixedUpdate(dt)` | 60 Hz while `state.simRunning` | All gameplay. `dt = FIXED_DT × clock.timeScale`. No wall clock, no `Math.random`. |
| `update(frameDt, alpha)` | every rendered frame, every state | Look input, interpolation of visible transforms, DOM writes (only on change). |
| `lateUpdate(frameDt, alpha)` | after every `update` | Work that needs the final camera: view-model, billboards, culling, listener position. |
| `debugState()` | on demand | JSON-safe, rounded to 1e-4, no functions, stable key order. |
| `dispose()` | page teardown, sandbox reload | Remove listeners, free GPU objects. |

### 3.3 The loop, the fixed timestep and time scale

```
frame(now):
  frameDt = min(now - last, 0.25);  last = now
  quality.onFrameTime(frameDt * 1000)
  acc += frameDt;  steps = 0
  while acc >= FIXED_DT and steps < MAX_STEPS_PER_FRAME:  tick();  acc -= FIXED_DT;  steps++
  if acc >= FIXED_DT: acc = 0                 # drop the backlog rather than spiral
  alpha = acc / FIXED_DT
  for s in SYSTEM_ORDER: s.update(frameDt, alpha)
  for s in SYSTEM_ORDER: s.lateUpdate(frameDt, alpha)
  render.render(frameDt, alpha)
  perf.endFrame()

tick():
  input.beginTick()                           # latches pressed/released edges for exactly this tick
  dt = clock.advance()                        # tick++, resolves slow-motion requests, returns FIXED_DT * timeScale
  handlePause()                               # 'pause' pressed or pointer lock lost -> state.request('paused')
  if state.simRunning: for s in SYSTEM_ORDER: s.fixedUpdate(dt)
```

- **Order: player → enemies → world → render → audio → ui**, for all three phases.
  Player first so the shot is resolved against last tick's enemy poses and its receivers
  run synchronously (GDD 6.8: everything on the click's tick). Enemies second so AI sees
  this tick's player position and applies damage through `ctx.player.applyDamage`. World
  third so triggers, the encounter director, puzzles and the story queue see final
  positions and this tick's deaths. Render, audio and UI consume.
- **Interpolation.** Anything that moves on screen keeps previous and current sim transforms
  (`core/interp.ts`) and blends by `alpha` in `update`. Teleports and spawns call `snap()`.
  Skeletal poses are not interpolated: `AnimationMixer.update(dt)` is called by the owner
  in `fixedUpdate`.
- **Look** is applied in `player.update` from `input.consumeLook`, per rendered frame,
  unsmoothed, and is never time-scaled.
- **Time scale.** `clock.slowMotion(scale, realSeconds, reason)` scales the `dt` handed to
  `fixedUpdate`; the tick rate stays 60 Hz, so stepping stays deterministic. Timers that
  must ignore slow motion use `clock.unscaledTime` (or count their own ticks in
  `fixedUpdate`). **`clock.tick` is not such a timer: it advances on every loop tick, also
  while the game is `paused` or `loading`** (`advance()` runs before the `simRunning` test;
  measured: half a second of pause advances it by 30), whereas `simTime` and `unscaledTime`
  advance only while the sim runs. A cooldown, telegraph or hint timer stamped from
  `clock.tick` would run out while a readable is open. With `options.reduceMotion`
  the call is a no-op. Users: last enemy of an encounter and boss phase breaks (×0.3 for
  0.3 s), the hush (×0.5 for 1.8 s), the kill sequence (×0.2 for 0.6 s).
- **Shader time** is `clock.simTime`. The grain seed is `clock.tick`. Nothing visual reads a
  wall clock, so two runs of one script give identical frames.
- **Test mode** (`?test=1`): the loop is not started. `__dbg.step(n, render)` runs `n`
  ticks, then, if `render`, one `update(FIXED_DT, 1)`, `lateUpdate`, `render.render`.

### 3.4 Game state machine

```
boot ──► title ──► loading ──► playing ◄──► paused
                      ▲           │  ▲         │
                      │           ▼  │         ├──► loading   (back to the last mark)
                      │          dead┘         └──► title     (quit)
                      │           │
                      └───────────┘ (respawn needs another resident set)
          playing ──► ending ──► title | loading (again)
          loading ──► title   (the run could not be loaded: polish round 2)
```

| State | Sim runs | Entered when | Notes |
|---|---|---|---|
| `boot` | no | page load | manifest and `always` set, `surface` set, level build, warm-up, tier detection. The loading screen shows. |
| `title` | yes | boot done; quit; end card "menu"; a load that failed | The overhang doorway shot, live: world not begun, player control off, camera at `player_start`. After a quit, and after a load that failed, core makes it so again behind the loading screen (`flow.ts` `titleShot`: `world.buildSet('surface')`, the other sets released, mood and exposure reset, she is stood on `player_start`) and only then asks for `title`: a quit goes `paused → loading → title` (reason `quit` on both). No checkpoint is committed in this state. |
| `loading` | no | Begin, Go on, a respawn or restart that changes resident set | `world.beginRun()` or `world.restoreCheckpoint()` runs here. |
| `playing` | yes | load done; resume; respawn | Pointer lock held (not required in test mode). |
| `paused` | no | `pause` action, pointer lock lost (`focus_lost`), a readable opened (`readable`: requested by world, closed by UI; 3.5) | `update` still runs; the frozen frame is redrawn under the menu. |
| `dead` | yes | `player/died` | 0.6 s fade, `ui_death` 1.2 s, then restore: control back within 3.0 s of the fatal tick (same set), else via `loading`. |
| `ending` | yes | the rim's end trigger | Player control off; 4 s of wind, then the end card over the live scene. |

`state.request()` refuses anything not in this table and returns `false`. Every transition
emits `game/state`. Core owns the machine; UI asks for transitions from its button
handlers (and calls `input.requestPointerLock()` and `audio.unlock()` inside the same click).

### 3.5 Who talks to whom

One-shot feedback is **event-driven**: render, audio and UI subscribe to gameplay events and
never get called for them. Direct calls exist only where a return value or a handle is
needed in the same tick.

| Caller | Direct calls it may make |
|---|---|
| `player` | `collision.*`; `HitReceiver.onHit` on what its rays hit; `render.vfx.muzzleFlash`, `render.addTrauma`; `clock.slowMotion` |
| `enemies` | `collision.*`; `player.applyDamage`; `render.vfx.acquireLine/acquireCard/ring/blobShadow`, `render.instances.*` (stakes, static bodies), `render.lamps.*`, `render.setEmissive`, `render.zoneVisible`; `world.flag()`, `world.doorState()` (nav gates), `world.builtZones`; `data.navPath` |
| `world` | `input.pressed('interact')`; `collision.*` (it supplies the level); `data.bindings/placement/nodeRest/cellAt/zoneAt`; `enemies.spawn/wake/clearEncounter/startBoss/playVignette`; `player.givePickup/giveLead/giveLineRounds/setKeptContext/teleport/setControl/takeStoneRound`, `player.applyDamage` (kill volumes such as `trg_bore_kill`, `DamageSource` `world`); `render.setVisible/setMood/setExposure/setLightLayer/setWrongFade/setSky/setOutline`, `render.instances.*`, `render.lamps.*`, `render.vfx.acquire*`; `assets.prefetch/activate/release`; `state.request`; `clock.slowMotion` |
| `render` | `assets.texture/get`; reads `player.eye/forward`, `world.zone`, `world.cell` |
| `audio` | reads `player.eye/forward`, `world.zone`, `enemies.threat`; emits `music/state` and, for captions, `story/say` |
| `ui` | reads `player.*`, `world.*`, `enemies.boss`; `options.set`; `state.request`; `input.requestPointerLock/captureNextCode`; `audio.unlock` |
| `core/debugHook` only | every system's `debug` surface (`PlayerDebug`, `EnemiesDebug`, `WorldDebug`); gameplay code never calls them |

Event rules: the bus is synchronous; payloads are scratch objects the emitter reuses, so a
listener copies what it keeps; no event is emitted every frame (continuous values are read
from `ctx`); a listener must not emit the event it is handling.

**One owner for each cross-cutting job** (so six builders do not solve these six ways):

| Job | Owner and rule |
|---|---|
| A sound with no domain event | Anyone **emits `audio/cue`**. There is no direct audio call: `AudioApi` has no `cue` method. |
| `music/state` | **Audio emits it**, derived from `encounter/*`, `boss/phase`, `game/state` and `enemies.threat`. Nobody else does. |
| `interact` | **World** polls `input.pressed('interact')` each tick and owns the focus ray: eye along the view, 2.2 m, `LAYER_FOCUS`, nearest hit; a focus exists when the nearest hit is an `INTERACT` volume (or a usable `SHOOTABLE`). World emits `interact/focus` when the focus changes and `interact/used` when it is used. The `kept` action (`F`) is the player's. |
| Readables | **World** emits `interact/used` and `readable/opened { key }`, then calls `state.request('paused', 'readable', 'readable')`. **UI** shows the viewer for that key and, on close, calls `state.request('playing', 'readable_closed')`; it emits nothing. World emits `readable/closed` when it hears `game/state` leave `paused` with pause reason `readable`, then plays any `thenLine`. |

### 3.6 Cross-module sequences (the load-bearing ones)

**A lead round** (all inside `player.fixedUpdate`, one tick):
1. `collision.raycast(eye, aim, 200, LAYER_SHOT, hit)`.
2. If `hit.receiver`: `receiver.onHit(hit, damage, response)`. Otherwise the response is
   `impact`, or `deflected` when `hit.flags & ColFlag.GRILLE`.
3. Emit `weapon/fired` (with the end point), then `combat/hit` (with the outcome).
   Render draws flash, tracer, impact, decal; audio plays the report and the confirm; UI
   shows the marker. The receiver's owner has already emitted its own events
   (`enemy/felled`, `knot/burst`, `shootable/hit` ...) inside `onHit`.

**A line round**: `collision.raycastAll(..., 60, LAYER_SHOT, list)`; walk the list near to
far; stop at the first entry that is static or dynamic geometry without `ColFlag.PIERCE`,
or whose response sets `stopsLine`. The player applies entry *i* at tick offset
`round(i × 2.4)` (40 ms apart), emitting one `combat/hit` each with `order = i`, then
`combat/line_resolved`. A line round does a flat 300 (GDD 6.2 revision 2: no weak-point
multiplier) and ignores the gate of a volume whose `gateIgnoredBy` lists it (a Tamper's
knots through the shut plate).

**Damage to the player**: the attacker fills a `DamageInfo` and calls
`ctx.player.applyDamage`. The player applies difficulty, the last-20-HP absorb, the grace
rule and god mode, and emits `player/damaged` or `player/died`.

**Encounters**: world's director reads `layout.encounters`, locks doors, calls
`enemies.spawn()` per wave by the GDD 10 conditions (the machine-readable wave fields
`atSeconds`, `cancelledIf`, `afterWaveDownSeconds`, `orAtSeconds`, `opensDoor` win over the
`when` text), counts `enemy/felled|freed|died`, emits `encounter/*`, requests the last-enemy
slow motion and decides drops (ammo floor, drop chance). Attack tokens, the alive cap
(never more than 6 outside the boss room), lanes and all behaviour are the enemies
module's. **A dormant or vignette member that is damaged before its trigger starts the
encounter:** enemies emit `enemy/damaged` as usual; the director, seeing it for a member of
an `idle` encounter, starts that encounter on the same tick. The boss is one call,
`enemies.startBoss`, after which the enemies module runs the phases and spawns its own adds;
world listens to `boss/*`.

**Story text**: any system emits `story/say { key }`. World's sequencer applies once-only
rules (every `nar_*` key plays at most once per run, `story.meta.rules.narrator_repeat`; the
flags are saved), queues (one line at a time, at most four waiting, hints dropped when busy)
and emits `story/line`, `story/card` or `story/caption`. UI displays; audio voices station
lines. No system writes player-facing text itself.

**The kept round** (GDD 6.6 revision 2): the six marks are lit and `F` is live from the
first tick of phase `p3a`. World tracks the marks and, while the player stands on one,
calls `player.setKeptContext(ctx)` with the bore target cylinder from the layout marker
`bore_opening` (`params.volume`: radius 3.0 m on the bore axis, from the kerb top at y −42.8
down to y −50). `F` → player emits `weapon/kept` (`loading`); enemies answer with the hush
(`boss/hush`) and swing the arm to the index opposite the occupied mark. While the round is
chambered the player tests its aim ray against that cylinder analytically each tick (no
collision query: the kerb, the invisible guard and the Windlass take no part) and exposes
the result as `weapon.keptAimLegal`, which the HUD's plumb glyph shows. Fire with a legal
aim → `weapon/kept` (`fired`); otherwise `weapon/dry_fire` (`kept_not_in_bore`). Enemies emit
`boss/proven` and free every Bider; render runs `vfx.provingRing` and `wrong_fade`; audio
stops the hum; world commits `cp_boss_proven`.

`checkpoint/saved`. On `player/died`: state `dead`; after the fade core (`flow.ts`) awaits
`world.restoreCheckpoint()`, calls `applySave()` in the order enemies, world, player and
requests `playing` (3.5).

is hidden, whatever its door's state: integration ruling, polish round 2), calls `render.setVisible(units)` and, on a cell

is the data.

The peg stair's first flight is the one place two resident sets meet: it is zone
`the_gallery` (set `underground`) and is walked while `surface` is resident. The rules:

1. **What is built.** `world.builtZones` is the resident set's zones plus, in the `seam`
   stage, `the_gallery`. A layout solid, marker or nav node is live when its zone is built,
   or when its `sets` (`params.sets` on a marker) contains the resident set (the layout
   flags flight 1, landing 1 and their shaft walls that way, so they exist under the shut
   hatch from boot). `stageZone` adds the rest of the gallery (flight 2 with `trg_set_swap`
   on it, the bay, the gallery), its props and its `chunk_gl_*` meshes. Colliders:
   `core/greybox.buildSolidColliders(layout, builtZones, residentSet)` then
   `collision.setStatic` (section 6).
2. **Which zone she is in.** `world.zone = data.zoneAt(feet, world.residentSet)`: the
   highest-priority zone *of the resident set* that contains the point. `tally_house`'s
   bounds reach down to y −5.5, so on flight 1, landing 1 and the top of flight 2 the zone
   is `tally_house` (mood, reverb, `m_prop` ambient, `save.zone`) until `trg_set_swap`,
   and `the_gallery` from the tick `buildSet('underground')` begins. It is never null on
   the critical path. The visibility cell there is `cell_tally_seam`.
3. **Triggers.** `trg_hatch_close` and `trg_set_swap` are gallery markers; both are live
   from staging and both require `enc_tally clear`.
4. **Nav.** The graph the enemies module walks is the nodes of `builtZones` (plus nodes
   whose `sets` contains the resident set); it is rebuilt on `world/built`. A link listed in `nav.gates` is passable only
   while `world.doorState(door)` is `open`: the hatch is `closed` or `ajar` for the whole
   of `enc_tally`, so the two risers can never path onto the stair.
5. **The hatch.** `closed` (a walkable lid) → `ajar` when `knot_hatch_latch` bursts (the
   `open` clip held at 15 %, a 0.3 m gap, the collider stays: impassable) → `open` when
   `enc_tally` is clear → `closing` when the player is inside `trg_hatch_close` with her
   feet at or below y −3.5 **and** her capsule does not overlap the leaf volume (it waits
   while she stands in the opening) → `closed`, collider on. Until `trg_hatch_close` fires
   she can walk back up into the hall; after it she cannot, and after `trg_set_swap` the
   stair is still there under a shut hatch.
6. **No checkpoint inside the seam.** `cp_tally_hatch` (the hall, `enc_tally` clear) is the
   last checkpoint before `cp_gallery_bay` (the stair foot). A death or a restart on the
   stair restores `cp_tally_hatch`: if the surface set is still resident, in place; after
   the swap, through `loading`. **Whenever a restore, a warp or a stored-save resume leaves
   the surface set resident with the flag `hatch_powered` true, world re-enters the `seam`
   stage (prefetch, activate, `stageZone`) before control is given.**
7. **Memory.** The `seam` stage holds `lm_gallery` beside the surface textures: 32.9 MiB of
   textures, 61.0 MiB with Low's render targets, 58.6 on `min`, 110.8 on High.
8. **Proof.** `tests/core/seam.test.mjs` (foundation, on the greybox): warp to
   `cp_tally_hatch`, then **walk by input** (`followPath('cp_gallery_bay')`) down flight 1,
   landing 1 and flights 2 and 3, rendering every tick on Low, and assert at
   every tick: grounded or falling less than 0.5 m, `world.zone` not null, `textureBytes +
   renderTargetBytes` ≤ 64 MiB; and once: the hatch closed before `trg_set_swap` fired, the
   set is `underground` at the foot, and walking back up ends under a closed hatch.

/**
 * The collision and query service. Implemented once in src/core/collision.ts (zero allocation per query).
 * Content is supplied by src/world (static colliders, doors) and by volume owners (enemies, puzzles, projectiles).
 * All positions are world space, metres.
 */
export interface CollisionWorld {
  // ---- content (load time or state changes; never per frame)
  /** Replace the static collider set. `positions` are world-space triangles (9 floats each); the per-triangle arrays are parallel. Builds the BVH. */
  setStatic(positions: Float32Array, triSurface: Uint8Array, triFlags: Uint8Array, triSolid: Uint16Array, solidIds: readonly string[]): void;
  clearStatic(): void;
  /** Switch every static triangle built from one layout solid on or off (solids with `dynamic` + `enabledBy`, e.g. the fallen loft ladder). */
  setSolidEnabled(solidId: string, enabled: boolean): void;
  /** An oriented box (rotation about Y only) on Layer.DYNAMIC. Half extents in metres. */
  addBox(cx: number, cy: number, cz: number, hx: number, hy: number, hz: number, rotYRad: number, surface: SurfaceType, flags: number, entity: EntityRef | null): ColliderHandle;
  setBoxTransform(h: ColliderHandle, cx: number, cy: number, cz: number, rotYRad: number): void;
  setBoxEnabled(h: ColliderHandle, enabled: boolean): void;
  removeBox(h: ColliderHandle): void;

  // ---- hit volumes (ray and overlap targets; they never block movement)
  addVolume(desc: HitVolumeDesc): VolumeHandle;
  setSphere(h: VolumeHandle, x: number, y: number, z: number, radius: number): void;
  setCapsule(h: VolumeHandle, ax: number, ay: number, az: number, bx: number, by: number, bz: number, radius: number): void;
  setVolumeBox(h: VolumeHandle, cx: number, cy: number, cz: number, hx: number, hy: number, hz: number, rotYRad: number): void;
  setVolumeEnabled(h: VolumeHandle, enabled: boolean): void;
  removeVolume(h: VolumeHandle): void;

  // ---- movement
  /**
   * Push a vertical capsule (feet at x,y,z) out of Layer.WORLD | Layer.DYNAMIC geometry.
   * Walkable surfaces (normal.y > walkableCos) push straight up so nothing slides on ramps.
   * Callers sub-step so that speed * dt / subSteps < radius.
   */
  resolveCapsule(x: number, y: number, z: number, radius: number, height: number, walkableCos: number, out: CapsuleResolve): void;
  /** Downward ray from (x, y, z). Returns the ground y, or NaN when nothing is within maxDrop. Fills outHit when given. */
  groundHeight(x: number, y: number, z: number, maxDrop: number, outHit?: HitResult): number;
  /** True when a capsule at this feet position touches nothing solid. */
  capsuleFree(x: number, y: number, z: number, radius: number, height: number): boolean;

  // ---- rays
  /** Nearest hit along a unit direction. One hit per entity (highest priority volume). Returns out.hit. */
  raycast(ox: number, oy: number, oz: number, dx: number, dy: number, dz: number, maxDistance: number, layerMask: number, out: HitResult): boolean;
  /** Every hit along the ray, near to far, at most MAX_LINE_HITS, one per entity. Does not stop at anything: the caller walks the list and stops per GDD 6.4. Returns out.count. */
  raycastAll(ox: number, oy: number, oz: number, dx: number, dy: number, dz: number, maxDistance: number, layerMask: number, out: HitList): number;
  /** True when no Layer.WORLD | Layer.DYNAMIC geometry lies between the points. Colliders whose flags intersect `ignoreFlags` are skipped (pass ColFlag.LOW | ColFlag.GRILLE for sight). ColFlag.BODY_ONLY colliders never block a ray or a sight line. */
  lineOfSight(ax: number, ay: number, az: number, bx: number, by: number, bz: number, ignoreFlags: number): boolean;

  /** Centre of an enabled hit volume of an entity (`part` null = its highest-priority volume). False when there is none. Debug, tests and aim assists. */
  volumeCentre(entity: EntityId, part: HitPart | null, out: Vec3): boolean;

  // ---- overlaps
  /** Volumes (not static geometry) touching a sphere. Returns out.count (list capacity 32). */
  overlapSphere(x: number, y: number, z: number, radius: number, layerMask: number, out: OverlapList): number;
  /** True when a sphere of `radius` swept from a to b touches a vertical capsule (feet at cap). Projectile-vs-player and lunge tests. */
  segmentHitsCapsule(ax: number, ay: number, az: number, bx: number, by: number, bz: number, radius: number, capX: number, capY: number, capZ: number, capRadius: number, capHeight: number): boolean;

  // ---- factories for the scratch structs (call once, keep)
  createHit(): HitResult;
  createHitList(): HitList;
  createResolve(): CapsuleResolve;
  createOverlapList(): OverlapList;

  /** Counters for the perf overlay: queries this tick, static triangles, boxes, volumes. */
  readonly stats: { rays: number; capsules: number; triangles: number; boxes: number; volumes: number };
}

export interface EventBus {

## 6. Collision and queries

**Ownership.** The engine (`CollisionWorld`, section 5.2) is implemented once, in
`src/core/collision.ts`, by foundation, because the player, enemies, world and four
sandboxes need it on day one and it must be allocation-free. **Content** is supplied by:

| Content | Supplier | How |
|---|---|---|
| Static level geometry | `world` | `core/greybox.ts: buildSolidColliders(layout, zones, residentSet)` turns every solid whose zone is in `zones`, or whose `sets` contains `residentSet`, into triangles with per-triangle surface, flags and solid index, then `collision.setStatic(...)`. `zones` is `world.builtZones` (3.6: the resident set's zones plus a staged zone). Rebuilt by `buildSet` and `stageZone` (a few thousand triangles: under 5 ms). |
| Sculpted terrain | `world`, from art | If a zone GLB contains a mesh named `collider_terrain`, its triangles **replace** that zone's solids of role `terrain` (manifest `collision: "mesh"`; today only `env_the_lip`). It must stay within 0.25 m of the solids; `tools/check-glb.mjs` samples every nav node of the zone and fails if the ground moved more than 0.3 m or any step on a nav link exceeds 0.35 m. |
| Dynamic solids (`dynamic` + `enabledBy`) | `world` | part of the static set, switched with `collision.setSolidEnabled(id, on)` |
| Doors, gates, shutters, baffle, bore door, cage gates, crates and barrels | `world` | `collision.addBox(...)` from the door marker's `size` (or the asset's `placeholder.size` for `collision: "box"` dressing); enabled while the door is `closed`, `ajar` or `closing` |
| Enemy and boss hit volumes | `enemies` | `addVolume` at spawn, moved each tick from the nodes in `EnemyDef.volumes`; disabled on death. A gated volume (`gatedBy`) stays enabled: its receiver treats a round that meets a shut gate as a plate hit unless the ammunition is in `gateIgnoredBy` |
| Shootables: jugs, latches, cords, rope, knots, ports, plates, breakables | `world` | `addVolume` on `Layer.SHOOTABLE` with a `HitReceiver`; radius from the marker's `hitRadius`. **Centre:** for an `instance` / `variant` binding, the marker position (the asset's `hitPoint` is there by construction: validated); for a `partOf` binding, the world position of the node on the owner's instance (`AssetInstance.node(name)`, re-read whenever the owner animates); for a binding with `follow`, the marker position plus the followed node's displacement from its rest position (the jugs ride the gate bar) |
| Things used with `interact` (levers, lockers, ammo boxes, readables, the stone, lift controls) | `world` | `addVolume` on `Layer.INTERACT` (sphere r 0.35 m at the marker unless the marker gives a size); never hit by shots |
| Stakes and canisters in flight | `enemies` | `addVolume` on `Layer.PROJECTILE` (stake r 0.30 for the player's ray) |

The bore target of the kept round is **not** a collider: it is the cylinder in `KeptContext`,
tested analytically by the player (3.6).

Rules:

- Surface type and flags of static geometry come from the layout solid (`surface`, `pierce`,
  `grille`/`skipsShots`, `low`, `stunsCharge`, `blocksBossFire`, `invisible`, `playerOnly` →
  `ColFlag.BODY_ONLY`). A `BODY_ONLY` triangle is seen only by `resolveCapsule`,
  `capsuleFree` and `groundHeight`; rays and sight lines pass through it (the invisible guard
  ring over the bore kerb's notches).
- Stairs are ramps in the layout. The 0.35 m step-up of GDD 5 is the player controller's
  job (lift, move, drop, using `resolveCapsule`, `capsuleFree` and `groundHeight`; the recipe
  is in `docs/requests/foundation-collision.md` 4).
- **Three engine properties a controller must handle** (pinned in
  `tests/core/collision.spec.ts`, "what a controller has to know", and tested against
  `dummyPlayer` in `tests/core/sandbox.test.mjs` and `walk.test.mjs`):
  (a) **the ledge lift is one radius, not 0.2 m**: `resolveCapsule` carries a capsule onto
  any walkable top below the centre of its lower sphere (0.35 m above its feet) when it is
  pressed into the ledge, and can leave it up to 0.14 m above that top (measured: a ledge
  0.30 m up → lifted 0.305 m; 0.34 m up → 0.475 m, in the air; 0.36 m up → a wall). So a
  controller's own lift adds to it (step 0.35 → up to 0.70 m) and **a jump reaches
  apex + 0.35 m**: with the GDD apex of 1.0 m the 1.3 m cover solids of the layout (four of
  them) would be mounted. Check the height really gained after every move, on the ground
  and in the air, and refuse a landing higher than the jump's apex (the stub player, apex
  0.86 m, mounts a 1.1 m box and not a 1.2 m one);
  (b) a `groundHeight` ray that starts inside a solid leaves through its underside and
  reports it: probe for a ledge from above anything climbable and refuse what is too high
  (the Tally House floor slab over the hatch stair was climbed from 0.49 m below this way);
  (c) the ground under the capsule's centre says nothing about its rim: when snapping down,
  resolve the capsule at the new height and keep the engine's answer.
- **Wedges**: two walls meeting at 5 degrees or more are resolved exactly (the capsule stops
  where it touches both, never inside either; unit-tested at 6, 8, 12 and 20 degrees at 5, 7
  and 12 m/s). Below 5 degrees the capsule can be squeezed 2 to 3 cm into them (the layout's
  sharpest wedge is 8 degrees, `ty_table_end` against `ty_wall_n`).
- No swept queries: depenetration cannot answer a true squeeze (a body at 60 m/s in a slot
  narrower than itself under a 5 cm ceiling is pushed through; the same room holds at
  12 m/s), and a capsule deeper than one radius inside a solid is not rescued (`capsuleFree`
  reports it: check a spawn or a teleport with it).
- The player sub-steps so that `speed × dt / subSteps < radius` (3 sub-steps cover 60 m/s).
- Enemies walk nav links (validated clear), so they need only `groundHeight` and steering.
  The Tamper's charge uses `resolveCapsule` and reads `wallFlags & ColFlag.STUNS_CHARGE`.
- Enemies and the player do not block each other; contact attacks use
  `segmentHitsCapsule`. Separation between enemies is steering.
- Line of sight for AI: `lineOfSight(a, b, ColFlag.GRILLE | ColFlag.LOW)`; at most four per
  frame across all enemies (the enemies module budgets them).
- A ray returns **one hit per entity**: the highest-priority volume the ray crosses (crown,
  lens and vents before bodies).
- `raycastAll` never decides what stops a round. The shooter does (section 3.6).
- `volumeCentre(entity, part, out)` is the one lookup from an entity to where to aim at it;
  the debug hook's `aimAtEntity` and `probe()` are built on it and on `raycast`, so they
  need nothing from the systems.
- Implementation constraints (from `docs/research/tech-web.md` 4, as built in
  `src/core/collision.ts`; foundation integration, section 18): one Float32 position array
  and one Uint32 index, `MeshBVH` built without `indirect` (strategy `CENTER`, leaf size 6).
  **Queries do not go through `bvh.shapecast` and use no `ExtendedTriangle`**: both allocate
  per call (about 0.26 KB and 24 B), and the requirement that wins is zero bytes per query.
  The engine walks the BVH's packed node buffers (`bvh._roots`, an internal of
  three-mesh-bvh 0.9.15) with an explicit `Int32Array` stack and its own segment / triangle
  closest-point routines on typed-array scratch; `setStatic` validates the node layout and
  throws if a different three-mesh-bvh ever changes it (the dependency is pinned). Per-triangle
  data (positions, surface, flags, solid) is copied once after the build into arrays in BVH
  triangle order (through the vertex index, because the BVH reorders the index buffer).
  Dynamic boxes and volumes are flat typed arrays tested linearly (at most 64 boxes and
  256 volumes; one more throws). Static solids must be closed and wound counter-clockwise
  seen from outside (back faces are ignored); a `collider_terrain` sheet must face up
  (`check-glb` enforces it on final art).

## 7. Asset pipeline

### 7.1 Flow

```
blender/<owner folder>/<id>.py ──tools/blender.sh──► blender/export/<category>/<id>.glb   raw: float attributes, no compression
blender/tex/<id>.py, zone scripts ────────────────► blender/export/tex|lm/<id>.png        raw textures and lightmaps
                 node tools/optimize-assets.mjs [ids…]
                                             ├► public/assets/<category>/<id>.glb     meshopt, quantised, no embedded images
                                             └► public/assets/tex|lm/<id>.webp        lossy for colour; near-lossless for lightmaps and R8 data
                 node tools/check-glb.mjs [ids…]                                      fails the build when an asset breaks its manifest entry
```

`node tools/build-assets.mjs [--only <id|owner>] [--placeholders] [--force]` drives all of
it, skips outputs newer than their sources, and builds in dependency order: textures →
props, weapons, enemies, boss → zones (they import props to bake them in place) →
optimise → check. Asset scripts take `--out <raw path> [--blend <path>] [--seed n]`, read
`design/assets.json` and `design/layout.json` for names, sizes and positions, and end with
`budget.assert_budget` and a preview render in `shots/<piece>/`. `public/assets/` is
committed; `blender/export/` is not. The owner folder of an asset is
`assets.json` `meta.ownerFolders[owner]` (`source` gives the full path).

The optimise step is **exactly the chain research verified** (`docs/research/tech-web.md`
12, decision 14), plus the removal of embedded images: `dedup`, `weld`, `resample`,
`prune({ keepLeaves, keepAttributes, keepExtras })`, remove every embedded image, `reorder`,
`quantize` of normals (10 bit), UVs (14 bit) and colours (12 bit, see below),
**POSITION stays float32** (quantising it rewrites node transforms),
`EXT_meshopt_compression`. **Never `join()` and never `instance()`**, on any file: both
discard node names and extras, which the manifest's node contract depends on. Repeats
inside a zone are copied and merged by the zone script (7.5); repeats at runtime go through
`render.instances`.

Colour precision is the one step research did not measure (it used 8 bit). Vertex light
needs more, so it is a **phase-2 exit criterion with a test** (`tests/pipeline/pipeline.test.mjs`):
a mesh whose `COLOR_0` holds 0.02, 0.5 and 1.0 goes through optimise and the real loader
and must come back within 1/4096 of each. If it does not, `COLOR_0` is taken out of the
`quantize` pattern and stays float32 (about 12 bytes a vertex before compression), and that
is the pipeline: no asset script changes either way.

### 7.2 What a GLB must look like

- One root node named by the asset id at the origin. The pivot is where the manifest's
  `pivot` text and `placeholder.anchor` say; nodes listed in the manifest's `nodePos` sit at
  those asset-local positions (within 0.03 m: `check-glb` measures them). Facing +Z
  (characters, doors, props with a front). The view-model is in camera space:
  **children of `scene.viewModel` are in camera space** (camera at the origin, looking down
  −Z, +Y up: as `art-weapons` authors the gun). **Render** gives the group the world
  camera's pose before its second pass (it copies `camera.matrixWorld` onto the group,
  `matrixAutoUpdate = false`) and draws it with its own 40° camera at that pose (polish round 3,
  lead ruling R6; 52° before, and still 52° in the core stub renderer and the asset viewer); a
  world-space position of a node under it (the `muzzle`) is therefore right after
  `render()` or after `group.updateMatrixWorld()`. **Player never transforms the group
  itself**, only what it added (kick, bob, sway on the instance root). `basicRender` does
  exactly this (`tests/core/sandbox.test.mjs`, "view-model: …").
- Names are snake_case, unique across nodes, meshes and bones.
- **Gameplay positions are empties or bones, never mesh nodes** (the optimiser may change a
  mesh node's transform). Code looks names up through `AssetInstance.node()`, which accepts
  only names listed in the manifest (`nodes`, `bones`).
- **Materials are names, not content.** A mesh's Blender material must be one of `m_frontier`,
  `m_pellam`, `m_sand`, `m_flat`, `m_mask`, `m_emis`, `m_prop`, `m_gun`. The runtime replaces
  it through `render.material()`; GLBs ship **no textures**. Shared textures and lightmaps
  are separate files listed in `assets.json` `textures`.
- **A zone GLB's static meshes use only the materials of their chunk** (`assets.json`
  `assets.<zone asset>.chunks[].materials`: at most four of `m_sand`, `m_frontier`,
  `m_pellam`, `m_mask`, `m_emis`). `m_flat` and `m_prop` do not occur in a zone GLB:
  embedded props and flat-coloured parts take the chunk's structure material, point UV0 at
  the trim sheet's uniform `flat` cell and carry their palette colour in `COLOR_0`
  (`blender/lib` does this when it merges an embedded prop).
- UV0 addresses the shared texture of the material (trim strip, palette cell, mask region).
  UV1 (`UVLight`) is the lightmap UV, and the lamp index on `m_emis` meshes. **Lightmapped
  and vertex-lit surfaces share one mesh:** a vertex-lit vertex of a lightmapped mesh puts
  its UV1 on the lightmap's neutral texel (7.4), so one shader variant and one draw call
  serve both.
- `COLOR_0` (linear): lightmapped vertices: tint × AO. Vertex-lit vertices: tint × baked
  light ÷ `VERTEX_LIGHT_SCALE` (2), clamped to 1. `AO` assets: tint × AO × gradients.
  `m_emis`: R intensity, G flicker group (0 steady, 0.5 flicker, 1 off until triggered),
  B `wrong_fade` participation.
- Mesh extras (Blender custom properties on the object): `bake` (`LM` when any vertex is
  lightmapped, else `VL`, `AO`, `UNLIT`), `lightmap` and `lightLayer` (texture ids, `LM`
  only), `lampCount` (lamp sets), `wind` (1 when the mesh sways; weights are height above
  the pivot unless a `_WIND` attribute survives), `breath` (1 on the static Biders: the
  breath weight is in UV1.x, 1 on the chest falling to 0, because `COLOR_0` is the tint on
  `m_prop`), `thin_ok` (below).
- Clips are NLA tracks named exactly as in the manifest, sampled at 30 fps, starting at
  frame 0, loops with identical first and last frames, root motion baked out. **Timing
  rule:** the manifest's `seconds` is the gameplay duration. Authored length is the nearest
  whole frame (within one frame of it); `AssetInstance.action()` sets the action's time
  scale so the clip lasts exactly the manifest's seconds. Gameplay timers never read a
  clip's duration.
- Bones listed in `codeDriven` must not be keyed. The asset store strips any track that
  targets them (the exporter writes T/R/S tracks for every bone in every clip).
- Draw calls per instance must not exceed the manifest's `drawCalls`. They are counted
  **one per mesh primitive** (one per mesh per material: the runtime joins nothing, so two
  meshes sharing a material are two calls), a lamp set being one `m_emis` mesh; variant
  nodes (manifest `nodes` realised as plain meshes and shown one at a time) count once, as
  the largest; a zone counts one per planned chunk mesh. `export.check_scene` counts the
  same way in Blender and `check-glb` on the shipped file. The budget is therefore one mesh
  per non-emissive material plus one per lamp set: use rigid skinning (one mesh, one weight per vertex) for
  multi-part animated assets. The manifest says which: a prop with more than one moving
  part, or a moving part beside static parts, has `skinned: true` and `bones` = `root` plus
  one bone per moving part (18 props, from `ia_ammo_box` to `ia_bore_door`). **A name
  listed in both `nodes` and `bones` is the bone** (`nodes` is every name code may look up);
  the other `nodes` are empties, lamp-set meshes or variant meshes. A prop whose whole body
  is its one moving part (`ia_yard_door`, `prop_door_frontier`) stays unskinned: an animated
  empty with the mesh as its child.
- **Thin geometry (Low has no anti-aliasing above the `min` tier).** A part must be at
  least 2 mm wide for every metre of the farthest distance it is normally seen from: 3 cm
  at 15 m, 6 cm at 30 m, 20 cm at 100 m (about 1.3 pixels at 720p). Anything thinner is
  fattened, turned into an alpha-tested card whose texture carries the pattern (`grille`,
  `louvre`), or drawn as a constant-pixel-width line by the VFX system. `check-glb` lists
  every connected mesh island longer than 0.5 m whose two smaller bounding dimensions are
  both under 3 cm (wires, rods, rails, pegs) and fails unless its mesh carries
  `thin_ok: <metres>`, the farthest distance it is seen from, and that distance satisfies
  the rule. Art-bible items this bites: pipe banks, peg rails, wires and cords, the grille
  catwalk, aqua strips, pump braces.

### 7.3 Placeholders and priorities

`tools/blender.sh -b --factory-startup -P blender/placeholders.py` (foundation) writes a
placeholder for **every** manifest asset and texture that has no final file, through the
same export and optimise path:

- Assets: the `placeholder.shape` at `placeholder.size`, positioned about the origin by
  `placeholder.anchor` (`base`, `sill`, `centre`, `top`, `back`, `back_base`, `hinge`; the
  meanings are in `assets.json` `meta.enums.placeholderAnchor`), flat category colour in
  `COLOR_0`, the asset's first material name; every name in `nodes` as an empty at its
  `nodePos` (the origin when it has none) (or a small mesh for lamp sets, with `lampCount`
  quads and lamp indices in UV1); for skinned assets an armature with every bone in
  `bones` (a `nodes` name that is also a bone is made once, as the bone, at its `nodePos`),
  the shape rigid-skinned to the first; every clip with the right name, loop flag
  and length, moving the root (or first bone) visibly.
- Zone assets (`placeholder.source = "layout-solids"`): the greybox of that zone's layout
  solids, split into the zone's chunks (7.5) and their materials, coloured by surface,
  vertex-lit by a fixed key, with the nodes above.
- Textures: correct size and format; mid-grey detail with the `flat` cell, the real
  palette, a flat lightmap that displays as mid-grey with its neutral texel painted.
- The root carries the extra `placeholder: true`. The generator never overwrites a file
  whose root lacks it; `LoadedAsset.isPlaceholder` and `node tools/asset-status.mjs` report
  what is still a placeholder, **by owner and by priority** (1.1).

Code is therefore always written against final names, pivots, node positions, clips and
durations. Art owners finish priority 0 before starting priority 1 (1.1).

### 7.4 Baked lighting

- **Lightmaps** are separate WebP files (sRGB, 8 bit, no mips, `flipY = false`,
  `channel = 1`). Stored value = Cycles diffuse light (direct + indirect, no colour) ÷
  `lightmapScale`. Runtime: `albedo × texel × lightmapScale`, applied in the world shader
  (not through three's `lightMap` slot, so no π factor is involved).
- **`lightmapScale` = `VERTEX_LIGHT_SCALE` = 2 for every lightmap** (`assets.json`
  `meta.vertexLightScale`; the validator enforces the equality). Every lightmap reserves a
  **neutral texel**: the 4 × 4 block at its top-left corner is painted white after the bake
  (`textures.*.neutralTexel`; on a light layer the same block is black). A vertex-lit vertex
  of a lightmapped mesh puts its UV1 at the centre of that block, so its light is
  `1.0 × lightmapScale = VERTEX_LIGHT_SCALE` and its `COLOR_0` displays exactly as it would
  on a pure vertex-lit mesh. This is what lets a chunk hold lightmapped walls up to 3 m and
  vertex-lit walls above in **one mesh per material** (7.5). `blender/lib/bake` paints the
  block, keeps bake margins out of it, and writes the UV1.
- **Light layers** are single-channel textures on the same UV1, added as
  `tint × weight × texel × lightmapScale`: `lm_tally_hatch` (aqua, weight 0 → 1 on
  `world/hatch_powered`) and `lm_bore_glow` (violet → aqua by `wrong_fade`, bottom-up by
  world height). This is how the art bible's "two layers" for the bore and the Tally
  fail-safe are delivered: one RGBA fill layer plus one R8 layer.
- **Vertex light** for everything above lightmap height and for static props:
  `COLOR_0 = tint × light ÷ 2`. With the bake targets of the art bible (key 1.30, ambient
  0.90) tint × light stays under 2; the bake clamps.
- **Static props cast and receive in place.** Assets with `placedBy: "zone"` (every
  `embedded` binding) are imported by the zone script from `blender/export/` (placeholder
  or final), placed at their layout solid or marker, included as shadow casters in the zone
  bake, vertex-lit in place, given the chunk's structure material (7.2) and **merged into
  the zone GLB**. They cost no draw calls and are never loaded on their own. Zones must be
  rebuilt after their embedded props change (the build driver tracks it).
- The bore chamber is one 60° sector baked once; the script then copies it five times
  about `bore_axis` (same lightmap UVs, copied vertex light) and merges the six. The
  gallery module likewise. Nothing is instanced: the copies are ordinary triangles and count
  in the triangle budget (they always did on the GPU).
- Strips that flicker (`strip_flicker`) are excluded from the bake. The peg-stair strips
  are baked lit: the stair cannot be seen before `daylight` is solved.

### 7.5 Chunks, visibility cells, instancing, dressing, lamp sets

**Zone chunks (one rule).** A zone GLB is authored in world coordinates (root at the
origin). Its static geometry is exported as exactly the meshes its **chunk plan** in
`assets.json` names: one mesh per (chunk, material), called `<chunk id>__<material>`, at
most four materials a chunk. Named drawn nodes (`drawnNodes`: rotor, lamp sets, plugs) sit
beside them. Draw calls of a zone asset = Σ chunk materials + drawn nodes, at most 16;
`check-glb` holds the file to its plan and `validate_assets` to the arithmetic. There is no
grid: the artist assigns every face to the chunk whose `box` (or, for a skyline chunk,
whose `part` / `solids` rule) contains it.

- **The numbers are computed, not estimated.** "Most triangles" is everything those rules
  allow to be drawn at once, whatever the camera faces: the visible chunks, the backdrop,
  every runtime prop standing in a visible chunk, the zone's dressing allowance, the
  heaviest set of enemies that can be alive (at most 6; the boss + 3), vignette actors,
  every body the encounters in view can leave behind, projectiles, dropped pickups, the
  gun and 2 000 triangles of effects. The model is `cellBudget` in
  `tools/validate_assets.mjs`; the generator stores its result in each cell and the
  validator recomputes it and **fails above 120 000 triangles or 100 / 150 draw calls**.
  `assets.json` `zones.<id>.triangles` and `.drawCalls` are the maximum over that zone's
  cells: they now mean *everything drawn while the player is in this zone*. The frustum
  always holds less.
- **Hidden means not visible.** The validator ray-tests every hidden unit of the same
  resident set against the layout blockout from the cell's nav nodes (standing and jump
  eye heights; doors treated as open, except a door to another resident set, which is shut
  whenever only one of the two is resident; `node tools/validate_assets.mjs --pvs` prints
  the whole matrix). A hidden unit that any ray reaches is an error
  unless the cell lists it under `accept` with a reason. Four are accepted today: the yard
  floor from the forecourt (through two gateways, 80 m off); the gatehouse roof from the hall
  (3 rays of 5 040, through the door); and the hall interior from the
  street and from the yard outside the door strip, which is covered by a plug.
- **Plugs.** `visibility.plugs`: a black panel in a doorway, a drawn node of the near
  zone's GLB. World shows it while the unit behind it is hidden (door shut or open: the final
  plank door has gaps, and a hidden interior showed through them as sky).
  One exists: `plug_door_tally` in `env_plenty_street`. From the yard an open Tally House
  door is a dark doorway; the interior is drawn from the 12 m strip in front of it
  (`cell_yard_door`), where the far east half of the street is given up in exchange.
- Art may not undo a rule: a chunk's geometry stays inside its `box`, and nothing in a
  skyline chunk (`part: "high"`) comes within 3 m of the path's ground.

**Instancing is runtime only** (`instanced: true`): one mesh, one material, no skin, no
clips per variant node. `render.instances.add(asset, node, …)` keeps one `InstancedMesh`
per (asset, node): pickups, jugs, bottles, coats, hats, boots, crates, static Biders,
stakes, canisters, cartridges. There is **no in-file instancing**: `EXT_mesh_gpu_instancing`
is never written (7.1). The bore's six sectors, the gallery's seventeen modules and the
Tally House's eleven chairs are copies merged into their chunk by the zone script. The
cost is download size only (about 0.4 MB for the bore after meshopt), not draw calls and
not triangles.

- **Variant nodes.** One GLB may hold several variants as sibling child nodes
  (`jug_intact`/`jug_broken`, `coat_long`/`coat_short`/`coat_shawl`, `stake_hot`/`stake_cool`,
  `note_lip`…); a `variant` binding or the code names the node.
- **Dressing** is placed by the zone artist, not by code: empties in a zone GLB named
  `inst_<nnn>` (instanced decoration) or `brk_<nnn>` (breakable: gets a hit volume, counts
  for the ammo floor), with extras `{ asset, node, wind? }`. World instantiates all of them
  generically. Each zone has a dressing allowance (`zones.<id>.dressing`: triangles, draw
  calls, the assets allowed there) that `check-glb` sums the empties against. Nothing taller
  than 0.35 m on a nav link (LEVEL.md "preserve").
- **Lamp sets.** Any mesh with material `m_emis` listed in `lampSets` is one draw call of N
  lamps; lamp *i* has UV1.x = (i + 0.5) / N on all its vertices. `render.lamps.setMask` or
  `setCount` lights them. This replaces per-lamp nodes (ports, listening ring, mark lamps,
  diagram lamps, bay lamps, proving marks, boss lamps, gauge, town windows).

Dynamic light sources are exactly the art bible's list. The world shader's pulse term
(`uPulse[2]`: position, radius, colour) serves the muzzle flash and the ring at the
seventh. No three.js light objects are added or removed after warm-up.

On the `min` tier the same materials run with `toneMapped = true` and
`renderer.toneMapping = CustomToneMapping` (8.2); nothing else about them changes.

**Tone map (ruled after the foundation's third critic round; it replaces "Neutral" in every
earlier text): a shoulder-only curve with no toe, the `TONE_MAP_GLSL` of `basicRender`
(exported with `installToneMap` and a JS `toneMap` by `src/core/tonemap.ts`), knee 0.8, on
all three tiers.** After exposure, a colour
whose brightest channel `m` is at or below 0.8 linear is displayed untouched; above it the
colour is scaled by `(0.8 + 0.2 · t / (t + 0.2)) / m` with `t = m − 0.8` (slope 1 at the
knee, the brightest channel approaches 1.0, hue kept). The grade follows it. Three's
`NeutralToneMapping` is not used: its toe subtracts up to 0.04 linear from dark colours
(steel 54,82,90 → 23,67,77; gun_blue 28,34,48 → 3,16,37), and `sandbox/viewer.html`, where
art judges colour, shows the shoulder curve. "No pixel under `#0B0D12`" rests on the
grade's lift.

**As built after polish round 3** (`docs/requests/code-render.md` 13 to 17; no contract change): the per-object uniform
block of `m_prop` / `m_gun` is five vec4 (`uObj[5]`: the three above, + rim rgb and the view-model flag, + the
view-model's rim direction); `SharedUniforms` carries `uHdr` in the free slot `uK[12].w`. The view-model takes its own
light rig from the mood (`M_VM_AMB`, `M_VM_KEY`, `M_VM_RIM`, fixed in view space), and the `GUN` branch mirrors a small
studio by the reflected eye ray (one more varying, no texture). `src/render/prewarm.ts` is GENERATED
(`node tests/render/gen_prewarm.mjs`): every material x mesh-shape pair of the stage is linked behind the loading
screen; run the generator again after an asset rebuild that adds or removes a material, a vertex-colour layer, a UV1
or a skin (`tests/render/prewarm.test.mjs` names the missing pairs). High: bloom threshold 1.15 of display white (it
was 1.0 of scene light), intensity 0.9, radius 0.8, emissive things drawn x 2.0; sun shadow opacity 0.55, and the
shadow pass (not `castShadow`) stops indoors.

**Polish round 5.** `SharedUniforms` slot `uK[15].w` is `uSheen` (High only; 0 on Low and min, where the branch is
skipped): in `WORLD_LIGHT` a lightmapped face mirrors a share of its own baked light at a grazing angle
((1 - N.V)^2; floors in full, walls 0.15, ceilings none; none where the face already draws near white). The value is

**Polish round 4.** `SharedUniforms` slot `uK[13].w` is `uPulseCap` (`PULSE_CAP` 0.6 / exposure): the muzzle pulse is

### 8.2 Tiers and the feature matrix

There are **two tiers a player can choose, Low and High** (CLAUDE.md, GDD 15, the
`ui_opt_gfx_low` / `ui_opt_gfx_high` strings), and one hidden tier below Low, **`min`**,
that exists so a machine that cannot hold Low has somewhere to go. There is no Medium.
The numbers are `assets.json` `tiers`.

- Content is identical on all tiers (no LOD chains). **Low is the product**; High adds
  light bleed, edge quality and a shadow; `min` gives up grain, the HalfFloat range (additive
  effects clamp at display white) and nothing else.
- **`min` is built in round 1**, by the render owner, as part of the tier work: it is the
  one answer to the risk nobody can measure here (a HalfFloat composer plus a four-tap
  world shader on a 2017 integrated GPU), and it is a small amount of code: skip the
  composer, set `renderer.toneMapping`, draw the vignette quad. The WebGL context is
  created with `antialias: true` only when the tier chosen at boot is `min`; it is always
  created with a depth buffer so a runtime demotion needs no new context. A demotion is
  remembered (`localStorage['keepseven.tier.v1']`), so the next boot of that machine starts
  on `min` with MSAA.
- **Why High is not MSAA ×4.** A 4-sample RGBA16F colour buffer with depth at 1920 × 1080 is
  about 95 MiB by itself and 168 MiB at 2560 × 1440: over the whole 128 MB budget. FXAA
  needs no target of its own. High's buffer is capped at 1920 × 1080 for the same reason
  (the page upscales beyond that).
- The drawing-buffer cap applies with the pixel ratio: the quality manager clamps the ratio
  so that neither `maxBufferHeight` nor `maxBufferPixels` is exceeded (an ultrawide window
  is limited by pixel count).

**Polish round 4 (High).** The merged pass starts with a contact-shade term read from the scene's own depth
(`ContactShadeEffect`: 20 depth reads a pixel, no extra pass, no extra target, no second scene draw; full-screen draws on
High stay 12); bloom takes its threshold, knee and intensity from the mood (8.1). `post.aoK.value.w = 0` switches the
shade off at run time, `= 2` shows it alone.

**Polish round 5 (High; Low and min untouched).** (1) *Dense lamp sets.* Every emissive thing is drawn `EMISSIVE_HDR`
over white on High; a lamp set of more than `DENSE_LAMPS` 8 lamps whose nearest neighbour stands within its own size
(only the Windlass's `gauge`; `LampInfo.dense`, `MaterialFactory.denseHold`) is instead held at `DENSE_OVER` 1.08 x the
mood's bloom threshold, never under `DENSE_MIN` 0.92 of display white: pips with dark gaps, not one white bar.
(2) *Contact shade.* The strongest of the sixteen taps is left out (one tap is the stipple), and a surface in a lamp's
own pool loses up to `AO_LIT` 0.7 of the shade between display levels 0.30 and 0.85 (`uAoExposure`); `AO_INTENSITY`
stays 10. No pass, target or program was added. (3) *Mood keys.* `MoodKey` is `MoodId | 'L5a' | 'L5c' | 'L6c'`:
`L6c` (the rock room of the proving lift on the rim) is L6 in everything but the dynamic ambient, key, key direction
and fill; `moodAt('far_rim', 'L6', y, z)` returns it beyond `RIM_CAGE_MIN_Z` 111.8. (4) *The flash.* `VfxApi.muzzleFlash
(kind, x, y, z)` is unchanged as a contract; with a view-model attached x, y, z now give the sprite's distance from the
eye and the centre of the world light pulse, and the sprite's direction comes each drawn frame from the drawn `muzzle`
node (`vfx.ts` `rideMuzzle`, called from `system.ts` `render()` after `poseViewModel()`); without a node, x, y, z as
given. `weapon/fired` mx, my, mz is unchanged (the true muzzle). `__dbg.ext.render.muzzle()` reports the drawn muzzle,
the sprite and the smoke start as frame fractions. (5) *Driving drawn frames on High from a test:* give the event loop
a turn every 8 drawn frames (`pace()` in `tests/render/prewarm.test.mjs`): the browser otherwise keeps what each frame
left behind (4.4 GiB against 1.4 GiB over the same leg).

### 8.5 Tier detection and adaptive resolution (`core/quality.ts`)

1. `?tier=min|low|high` wins, then `options.graphics` (`low` or `high`), then a stored
   demotion (`keepseven.tier.v1` = `min`).
2. With `auto`: renderer string (`WEBGL_debug_renderer_info`, falling back to
   `gl.RENDERER`): software → Low; known integrated → Low; unknown → Low; known discrete
   or Apple M → High.
3. `render.benchmark()` behind the loading screen (8 additive full-screen passes into a
   1280×720 target, synced by a 1-pixel read, median of 5) may move the guess one step:
   under 0.6 ms High; over 4 ms `min`; else Low. Thresholds are untested on real GPUs.
   (A boot that lands on `min` this way recreates the renderer once, with context MSAA,
   before any asset is activated.)
4. Adaptive pixel ratio: the target is **the display's own frame interval, never tighter
   than 16.7 ms**. The first 60 `requestAnimationFrame` deltas (the title screen) are
   measured: a steady cadence at 60 Hz or faster gives 16.7 ms; a steady 50 / 48 / 30 Hz
   cadence is checked once by dropping to the minimum ratio for 50 frames (a display's
   cadence does not answer to resolution, load does) and becomes the target if it does not
   change; anything irregular keeps 16.7 ms. Each sample is the median of the last five
   deltas, clamped to twice the target, then an EMA (0.1). Over by 15 % → drop
   proportionally (`ratio × sqrt(target / ema)`, steps of 0.1) with a doubling back-off that
   **resets after a probe upward has held for 120 frames**; 180 good frames → probe up one
   step. A target above 16.7 ms is given up as soon as 60 consecutive frames come in
   faster. Bounds from 8.2, upper bound scaled by `options.resolutionScale`. A change
   reallocates render targets, so there is a 30-frame cooldown. When the allowance grows back (the window shrinks back, fullscreen is left,
   `resolutionScale` is raised) and the controller is not holding the ratio down, a ratio
   that sat at the old allowance follows the new one; a real back-off survives a resize.
   **Polish round 2:** a drop that is not a failed probe is at most two steps a decision
   (under vsync a frame that misses by 2 ms reads as 33.3 ms, and the square root took 0.9
   to 0.6 where 0.8 held), and there is no dead band: an EMA more than 6 % over the target
   for 120 frames gives one step (a steady 18 ms without vsync quantisation sat at ratio 1
   for ever).
5. At the minimum ratio and still over (by 15 %) for **15 s** (5 s until polish round 2:
   one stall of the machine did it): if the last 60 frames are steady on a
   50 / 48 / 30 Hz cadence and nothing faster was seen this session, that cadence becomes
   the target (no demotion). Otherwise demote one step, High → Low → `min` (emits
   `quality/changed` with `demote`). **A demotion to `min` is not stored when it happens,
   and it is not for ever.** `min` on budget at its full ratio for 60 s tries Low again
   (`quality/changed`, reason `detect`), at most three times a session, 60 / 120 / 240 s
   apart; a promotion that holds for 7 200 frames forgets the demotion (and removes a
   stored one). `keepseven.tier.v1` is written only when a promotion was tried and
   starved again, when `min` held for 180 s with no way up, or when `min` itself starves.
   A stored demotion at boot is a hint: the session starts on `min` and tries Low once.
   `min` chosen by `?tier=` is never climbed out of. `min` at its minimum ratio on a steady
   slow cadence means a frame cap arrived in mid-session: the cadence becomes the target
   and the tier the session demoted from is restored (`quality/changed`, reason `detect`);
   nothing is stored. Otherwise `min` at its minimum ratio has nowhere to go: the overlay
   says so. Real-GPU behaviour of steps 4 and 5 is untested (unit tests on synthetic frame
   times only).
6. The options menu shows Auto / Low / High. While `min` is running it shows Low as
   selected; choosing Low or High explicitly clears the stored demotion.
7. Test mode: no detection, no adaptation. Tier is `?tier=` (default `low`), pixel ratio 1.

### 8.6 How budgets are measured

- `ctx.perf` (`PerfMonitor`): the loop times `fixedUpdate`, `update`/`lateUpdate` and
  `render` per system with `performance.now()`; render fills the renderer counters in
  `collectStats` (`renderer.info` with `autoReset = false`, reset once per frame, so post
  passes are included); `textureBytes` is an estimate from the manifest's `gpuBytes` of
  active textures plus bone textures; `renderTargetBytes` from the buffers actually
  allocated (the same per-pixel figures as 8.4, at the current buffer size); `cell` is the
  visibility cell the frame was drawn from.
- **Perf overlay**: `F3`, or `?perf=1`. Shows `PerfStats`, the current cell and its computed
  bound from `assets.json`, the tier caps, and a 120-frame bar of `frameMs`. Red when over.
- **Machine-readable**: `window.__dbg.perf()`, `perfPeak()`, `perfRun(ticks)` (section 11).
- Headless Chromium has no GPU: `frameMs` (JS only), draw calls, triangles and texture
  bytes are the evidence. JS budget: `frameMs` ≤ 4 ms on a mid-range CPU; in SwiftShader runs
  judge `simMs + updateMs` (pure JS) and treat `renderMs` as relative.
- Allocation: every piece measures it with
  `measureAlloc(game, body, { warm, batches, perBatch, ring, arg })` of `tests/harness.mjs`
  (the browser runs with `--js-flags=--expose-gc --enable-precise-memory-info`):
  `body(dbg, ticks, arg)` runs in the page and runs exactly `ticks` ticks of the path
  (`(dbg, n) => dbg.step(n, false)`, or one `dbg.step(1, true)` per tick for a tick plus a
  frame). It warms the path for 3000 ticks, then takes the median of 10 batches of 60 ticks
  between `gc()` calls, with the debug event ring off (`ring: false`; the ring clones every
  payload, about 72 B per event, a cost a production build does not have). Returns
  `{ perTick, samples }`. Below 3000 ticks of warm-up the figure is JIT and inline-cache
  work, not the path: a tick plus a rendered frame reads 6.8 KB after 300 ticks, 1.8 KB
  after 3000, 1.5 KB after 12000. **The ceiling is 6 KB per tick and 6 KB per tick plus
  rendered frame** (`tests/core/alloc.test.mjs` asserts both; core + stubs measure 0.4 KB
  and 2.8 KB).

## 9. Data flow from design to runtime

```
design/layout.json ─┐                         ┌─ world: zones, colliders, markers → doors, pickups, interactables, puzzles,
design/story.json  ─┼─ core/data.ts (import) ─┤         triggers, encounters, checkpoints, rides, lights' switches, visibility cells
design/assets.json ─┘   typed, id-indexed     ├─ enemies: nav graph, spawn markers, lanes, bays, firing points, vignette anchors
                                              ├─ render: zone bounds and moods, sun vector, tiers, units
                                              ├─ ui / audio: every string and caption by key
                                              └─ core/assets: what to load per resident set and stage
```

- The three files are bundled by Vite as JSON imports (`resolveJsonModule`), cast to the
  types in section 5.3. `core/data.ts` builds the id maps once. In test and dev mode it
  also runs a cheap structural check and throws on a missing id.
- `design/assets.json` is generated **from** `design/layout.json` (opening sizes, cage
  sizes, the table footprint, the loop height are read from the markers and solids), so a
  layout change that moves an opening changes the manifest on the next
  `node tools/gen_assets.mjs`, and `validate_assets` fails until it is regenerated.
- Story keys in layout params (`lines`, `cards`, `objective`, `hints`, `caption`) are
  played by world's sequencer; `tools/validate_layout.mjs` checks they exist and that each
  is wired once.
- Blender scripts read the same three files with `json.load`. Game space to Blender:
  `(x, y, z) → (x, −z, y)`.
- Gameplay numbers that are not placement (damage, speeds, timings) are in the owner's
  `defs.ts`, copied from the GDD with the section number in a comment.
- `data.navPath(a, b)`: a call costs 0.0004 ms / about 0.1 KB for a short hop and 0.025 ms /
  1.2 KB for the whole critical path (the returned array; the search allocates nothing).
  Call it on a repath event, not every tick. Core-internal
  `GameDataImpl.navPathInto(a, b, openOnly, out)` fills a caller's array.

### 9.1 Layout marker → runtime object

World never hardcodes an asset id for a marker and never interprets a binding by its
shape. `data.bindings(marker)` returns the marker's bindings in the one lookup order
(a door marker through `bindings.door[id]`, and its `params.interactable` is **not** a
second binding; a `puzzle_element` without `params.interactable` through
`bindings.puzzleElement[id]`; then `params.interactable`, `params.pickup`,
`params.readable`, `params.prop`; an `enemy_spawn` resolves only its `params.entrance`: the
grate it climbs out of. Its `params.prop`, the kneeler's cup, is the hand prop of its
vignette and is attached by the enemies module). Every binding has a **`mode`**, and the
mode says what world does:

| `mode` | World does | Examples |
|---|---|---|
| `instance` | instantiates the asset once for this marker (through `render.instances` when the asset is `instanced`), at `data.placement(marker, binding)` | `ia_ammo_box_*` → `ia_ammo_box`; `shutter_s` → `ia_shutter`; `door_bore` → `ia_bore_door`; `lift_depart_hall` and `lift_arrival_bore` → `ia_lift_cage` (two instances); `prop_tally_seated` → nine `bider_table_static` (`per: "seats"`) |
| `variant` | as `instance`, showing only the variant node `node` | `ia_jug_n` → `ia_jug` / `jug_intact`; `ia_stone_round` → `prop_cartridge_kept` / `round_violet` |
| `partOf` | instantiates **nothing**: the marker is the part `node` (or the root) of the instance that marker `owner` created. World resolves it to `ownerInstance.node(node)` and attaches the hit or focus volume there | `ia_latch_s` → `latch` of `shutter_s`'s `ia_shutter`; `ia_cloth_cord` → `cord` of `prop_share_cloth`; `sec_loft_bell_rope` → `rope` of `sec_loft_bell`; `ia_ask_port_1…8` and `pz_listening_lamps` → `port_n` / `listen_lamps` of `door_bore`'s `ia_bore_door`; `door_lift_cage` → `gate` of `lift_depart_hall`'s cage; `door_proving_lift` and `ia_proving_lift` → `gate` / `control` of `lift_depart_bore`'s `ia_proving_lift_cage`; `ia_hatch`, `ia_yard_door`, `ia_baffle` as interactables → their own door instance |
| `zoneNode` | instantiates nothing: `node` (lamp `index`) of a zone GLB that is already in the scene | `ia_proving_mark_n` → `env_the_bore` / `mark_glows` [n − 1]; `prop_wind_pump` → `env_plenty_street` / `pump_rotor` |
| `embedded` | instantiates nothing: the mesh was merged into the zone GLB by the zone script; world adds only the interaction (a focus volume, a readable) | every `readable`; every `solidProp` and `zoneEmbedded` entry |
| `actor` | nothing: the enemies module spawns and animates it | `bindings.enemy.*`; `prop_watcher` → `enemy_bider` (vignette `vig_watcher`; fallback `bider_seated_static` if GDD 20.1 row 2 is cut) |

`validate_assets` fails on a binding without a mode, a `partOf` whose owner does not
instantiate that asset, a `zoneNode` outside its lamp set, a zone-embedded asset bound for
runtime, and two instances of one non-instanced asset whose placeholders overlap (one object
bound twice).

### 9.2 Where it is placed: the marker, the pivot and the hit point

**Rule: a marker's `pos` is the asset's pivot, unless the binding carries an `offset`.**

- `data.placement(marker, binding, out)`: `pos = marker.pos + R · (offset × scale)`,
  `rotYRad = radians(marker.rotY) + π`, `scale = binding.scale ?? 1`. The π is because an
  asset's front is +Z and a marker's `rotY` 0 faces −Z; `R` is that rotation, and `offset`
  is in asset-local metres. `space: "world"` means identity (the asset was authored in
  place: `prop_well_sweep`).
- The layout's markers are where the **player** aims or stands (a jug's body, a latch, a
  ring's centre, an opening's centre); an asset's pivot is where the **artist** hangs or
  stands it (a cord top, a post base, a hinge). `offset` is the vector between the two,
  written once in the manifest, so neither document has to bend:

| Marker | Is | Asset pivot | `offset` |
|---|---|---|---|
| `ia_jug_1…7` | the jug's body centre (its hit sphere) | cord top | `[0, 0.81, 0]`; jugs 1–6 also `follow` `hook_n` of the gate |
| `knot_*` | the knot's centre | collar back centre | `[0, 0, −0.08]` (× 1.25 for `knot_a/b/c`) |
| `ia_yard_bell` | the bell | post base | `[0, −2.2, 0]` |
| `ia_range_plate_n` | the plate's centre | hook | `[0, 0.45, 0]` |
| `shutter_s/m/n` | the opening's centre | hinge axis (bottom edge) | `[0, −0.45, 0]`; the `latch` node is 0.55 m below the pivot: the `ia_latch_*` marker |
| `prop_share_cloth` | the cloth's centre | cord top | `[0, 0.855, 0]`; the `cord` node is the `ia_cloth_cord` marker |
| `sec_loft_bell` | the bell | hoist arm tip | `[0, 1.05, 0]`; the `rope` node is the `sec_loft_bell_rope` marker |
| `pz_sighting_loop` | the ring's centre | post base | `[0, −2.018, 0]` |
| `pz_proving_mark` | the step's top | step base | `[0, −0.15, 0]` |
| `ia_lift_lever` | the lever grip | pedestal base | `[0, −1.2, 0]` |
| `door_bore` | sill centre | disc centre | `[0, 1.5, 0]` |
| `ia_hatch` | bottom of the lid | opening centre at floor level | `[0, 0.3, 0]` |
| `door_jug_gate` | sill centre, mid-wall | bottom centre of the hurdle | `[0, 0, −1.1]` (the gate hangs on the forecourt face of the 2 m wall) |
| `ia_yard_door`, `door_alley`, `door_tally` | sill centre | hinge axis at ground | half the opening width along −X (and −0.44 in Z for the yard door, which hangs on the wall's street face) |
| `day_cell`, `ia_cradle`, `prop_station_plate_4` | the face | back centre | a few centimetres along −Z |

- **Hit volumes cannot drift from what is drawn.** An asset the player shoots as a whole
  declares `hitPoint` (asset-local); the validator requires `offset = −hitPoint`, so the
  marker (the centre of the hit sphere, section 6) is on the visible target. A part the
  player shoots is a node with a `nodePos`; the validator requires that node's rest
  position on the owner's instance to equal the part's marker (tolerance 0.06 m; 0.6 m for
  the two cage gates, whose door markers sit mid-wall). `check-glb` then holds final art to
  `nodePos` within 0.03 m, and the placeholders are built from the same numbers.
- The validator also places every placeholder at its marker and fails when the marker is
  outside it, when a floor-standing asset's base is not on a surface, when a door asset
  does not fill its marker's opening, and when a ride's cage asset is not the layout's cage.

## 10. Save, input, options

### 10.1 Checkpoints and save

- One slot. `localStorage['keepseven.save.v1']` holds `SaveData` as JSON; written at every
  `checkpoint/saved`; cleared on reaching the end card. A save whose `version` differs is
  ignored. In test mode storage is an in-memory object unless `?persist=1`.
- `SaveData = { checkpoint, tick, player, world, enemies }`; each part is produced by that
  system's `captureSave()` and must round-trip through `JSON.stringify`.
- Floors are applied by the player on `applySave`: `max(saved, 60)` HP, `max(saved, 18)`
  reserve, full cylinder of lead, the saved line rounds (GDD 5). `cp_gallery_baffle`
  restocks the bay locker (world).
- World saves puzzle, door (including `ajar`), pickup, locker, breakable, once-flag (every played `nar_*` key), vignette and stats state.
  On restore the current encounter resets; its freed and felled are removed from the counts
  (world keeps per-encounter tallies and commits them on `encounter/cleared`).
- Enemies save the boss phase, `parleyHeard`, deaths in the phase (mercy rule) and the
  static bodies that persist.
- Respawn target is the checkpoint marker's `pos` and `rotY` from the layout.
- Stored-save resume (`Go on`): `loading` → `assets` for the checkpoint zone's set →
  `world.beginRun(save)`. A restore that leaves the surface set resident with
  `hatch_powered` true re-enters the `seam` stage first (3.6 rule 6).

### 10.2 Input mapping

| Action | Default codes | Notes |
|---|---|---|
| `forward` / `back` / `left` / `right` | `KeyW` `ArrowUp` / `KeyS` `ArrowDown` / `KeyA` `ArrowLeft` / `KeyD` `ArrowRight` | arrows mirror WASD |
| `fire` | `Mouse0` | hold-to-repeat is an option, handled by the player |
| `reload` | `KeyR` | |
| `line` | `KeyQ` | |
| `kept` | `KeyF` | |
| `interact` | `KeyE` | |
| `sprint` | `ShiftLeft` | hold or toggle (option) |
| `jump` | `Space` | |
| `pause` | `Escape`, `KeyP` | Escape also releases pointer lock (browser), which pauses by itself |

`Mouse2` is unbound and its context menu is suppressed. Keys are tracked by
`KeyboardEvent.code`; repeats ignored; all keys released on blur, visibility change and
lock loss; mouse deltas above 400 counts dropped; `preventDefault` on Space, Tab and arrows
only while locked; Ctrl is never bindable. `pressed()` edges are latched until a tick
consumes them, so a click between ticks is never lost and never seen twice. Rebinding
uses `input.captureNextCode`. The test hook injects through the same functions.

Entering `playing` (from any state), and `setGameplayEnabled(true)` after `false`, drops
every press and release edge not yet consumed, except a `pause` press unless the state came
from `paused`. Held levels are kept. So the click or key that drives a menu is never a
gameplay press, and UI and player need no code for it. Gaining the pointer lock drops the edges too, so the
click that takes the pointer is never a shot. When both lock requests are **refused** (Chrome
refuses a re-lock for about 1.25 s after `Esc`), input emits
`input/pointer_lock { locked: false }` and the loop requests `paused` (`focus_lost`): the
click-to-resume plate returns instead of a game that plays with a dead mouse.

### 10.3 Options

`localStorage['keepseven.options.v1']`, written on every `options.set`, merged over the
defaults of GDD 15 on load (unknown keys dropped, values clamped). `options/changed` fires
with the key; systems apply changes live (sensitivity and FOV in the player, volumes in
audio, graphics in the quality manager, subtitles in UI). Difficulty may change mid-run.

The core stubs (`src/core/stubs/`) implement all three `debug` surfaces as no-ops that
return the empty value, so the hook is complete from phase 2 and each gameplay builder fills
in its own surface. `ext.*` is for extras only; nothing a critic's playthrough or a GDD 21
acceptance test needs may live there, with one exception:

**`ext.core` is core-owned, present on every page and stable**: it holds what the frozen
`DebugHook` interface (version 2) has no method for. `stepAsync(n, render)`,
`untilAsync(condition, maxSteps)`, `busy()`, `ran()`, `idle()`; `setSeventh(state)`
(`PlayerDebug.setSeventh`); `tokens()` (`EnemiesDebug.tokens`);
`damage(amount, kind?, source?, ox?, oy?, oz?)` → applied damage (`PlayerApi.applyDamage`
with a scratch `DamageInfo`: grace, the last-20-HP absorb and the damage arc can only be
driven this way, `setHealth` goes round them); `timeScale()`; `playerExtra()` →
`{ control, controlReason, keptAimLegal, shotsFired }` (`control` is the last
`player/control` event, `null` before the first); `ctx()` → the `GameContext` (page-side;
`__dbg.ctx` also works at runtime but is a private field of the implementation);
`recordEvents(on)`, `capsuleFree(x, y, z, radius, height)`, `collisionCounts(reset)` →

fields are candidates for `DebugHook` version 3 and `DebugPlayerState` (they change
`hash()`); until then this paragraph is their contract. Other helpers beside the contract:
`ext.sandbox.room / boxRoom / activate / loadOverlay / origin` (sandbox pages),
`ext.assets.report / isPlaceholder`, `ext.viewer.project / coverage / firstPerson / pose /
setBone / setClip` (the viewer), and, **on the stubs only** (they go when the real system takes the slot),
`ext.world.setDoor / setFlag / showAll`, `ext.player.fly / camera`,
`ext.render.addInstances / unitVisible / zoneVisible / moodLook / moodTint /
viewModelCoverage / viewModelProject`, `ext.enemies.setBoss`.

Semantics that tests rely on:

- **Determinism.** With the same build, seed, tier-independent script and viewport,
  `hash()` after N steps is identical across page loads **and across tiers**; screenshots
  are identical for one tier on this machine. Anything that breaks this is a bug in the
  system that introduced it (wall clock, `Math.random`, iteration over an unordered set,
  per-frame logic in `update`).
- `step(n, render)`: input set by `setKeys`/`setActions` stays held; `tap()` holds for its
  tick count then releases; `look()` deltas apply on the next tick's frame; `setAim`,
  `aimAt*` set the view at once.
- `stepUntil(cond, max)` evaluates the condition after every tick. Event conditions match
  the first event logged after the call began.
- **No tick runs while a flow job is pending** (a respawn, `restart_checkpoint`, a warp, the
  start of a run): those are promise chains and cannot settle inside a synchronous call.
  `step`, `stepUntil`, `perfRun`, `walkTo` and `followPath` stop there and return what they
  did (`ext.core.ran()` = ticks run by the last call; walks return `dead` or `state`);
  `step`, `stepUntil` and `perfRun` print one `console.warn` (the first time only) when they
  return short for this reason. `ext.core.stepAsync(n, render)` and
  `ext.core.untilAsync(condition, maxSteps)` let the job settle and run the rest;
  `tests/harness.mjs` `step`, `until` and `run` use them, so the tick a restore lands on is
  the same however a script is batched. A world's `restoreCheckpoint` / `beginRun` must
  therefore never wait on the simulation (the hook throws after 30 s).
- `tap()` is pressed and counted off by the loop's own per-tick hooks, so it behaves the
  same under `step()` and under the real-time loop.
- `setTier`, `solvePuzzle`, `clearEncounter`, `spawnEnemy` and `setBossPhase` throw
  `__dbg.<method>: unknown id '<x>' (<the valid ids>)` for an id outside the manifest's
  tiers / the four puzzles / the six encounters / the `EnemyKind` and `BossPhase` unions;
  `walkTo`, `teleport`, `aimAt`, `setAim`, `look` and `spawnEnemy` throw for a non-finite
  number. `state()` writes a non-finite number as 0 (JSON has no NaN) and records the
  first one, with its path, in `error`, which fails the test.
- **Walking.** `walkTo(x, z)` and `followPath(to)` move the player **by input**: each tick
  they turn the view toward the next waypoint, hold `forward` (and `sprint`) through
  `input.injectAction`, and run one tick, so collision, step-up, doors, triggers and the
  set swap happen as they do for a person. They are synchronous, never render, and restore
  the held input set on return. `followPath` walks `layout.nav` node to node (the next
  node is taken when within 0.4 m horizontally, or 0.8 m when the node after it is in line
  of sight), stops with `gate` before a link whose door is not `open`, with `portal` at a
  lift ride, with `stuck` after 45 ticks without 0.05 m of progress, and with `dead` or
  `state` if the game leaves `playing`. `followPath('critical')` follows
  `nav.criticalPath` from the nearest node on it. Both are deterministic.
- `start()` and `checkpoint()` are async (they may swap resident sets); everything else is
  synchronous.
- `state()` is rounded to 1e-4 and JSON-safe. `events()` returns clones; the ring keeps
  4096 entries; `seq` increases by one per event.
- `perf()` describes the last rendered frame; `perfRun(ticks)` renders every tick and
  returns per-field maxima: use it for "worst tick of this fight" budgets.
- `error` holds the first uncaught error; the harness fails a test when it is not null.
- `ext.<name>` holds helpers registered with `ctx.debug.register` (for example
  `ext.audio.render(cue)` returning peak and duration from an `OfflineAudioContext`,
  `ext.render.pixel(x, y)`).

## 13. Coding standards

- **TypeScript strict.** `tsconfig.json`: `target es2022`, `module esnext`,
  `moduleResolution bundler`, `lib ["es2023","dom","dom.iterable"]`, `types ["vite/client"]`,
  `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`,
  `noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`, `isolatedModules`,
  `moduleDetection force`, `resolveJsonModule`, `allowImportingTsExtensions`, `skipLibCheck`,
  `noEmit`; `include ["src","sandbox","tests"]`. No `any`, no `@ts-ignore`; `as` casts only at
  JSON and library boundaries. `npx tsc --noEmit` is clean before a piece is done.
- **No per-frame allocation** in `fixedUpdate`, `update`, `lateUpdate`, event handlers and
  anything they call: no `new`, no array or object literals, no closures, no
  `map/filter/forEach/spread`, no string building. Module-level scratch objects; pools with
  swap-remove (`core/pool.ts`) sized to the GDD caps (decals 48, stakes 8 + 18, rings 2,
  threads 6, enemies 6 + boss + 3, line hits 16); out-parameters instead of returned objects;
  hot numeric state in fields or typed arrays, not captured `let`s. Allocation is allowed
  in `init`, `start`, load, state transitions and test-only code.
- **Determinism.** Gameplay reads time only from `dt` and `ctx.clock`, randomness only from a
  stream forked once (`ctx.rng.fork('<module>')`); never iterate a `Set`/`Map` whose order
  depends on timing where order matters; no gameplay in `update`.
- **Events.** Names `domain/event`; payload fields are primitives; emit from reused scratch
  payloads.
- **Naming.** Files `camelCase.ts`; types `PascalCase`; constants `UPPER_SNAKE`; ids, node
  names, clip names, story keys and event names are the strings in the design files and
  this document, never retyped variants. Units in names when not metres/seconds/radians
  (`yawDeg`, `frameMs`).
- **Text.** No player-facing literal strings in code: `ctx.data.ui(key)` / `line(key)`.
- **Errors.** Fail loudly at load (unknown asset id, missing manifest node or clip, missing
  story key, marker without binding) by throwing; in the loop never throw: guard, log once
  through `console.error` (which the harness treats as a test failure) and continue. An
  event handler that throws is caught by the bus and reported.
- **three.js.** `matrixAutoUpdate = false` on static objects; `frustumCulled = false` only
  for the view-model, sky and shader-displaced meshes; `SkeletonUtils.clone` for skinned
  instances (the asset store does it); every patched material sets
  `customProgramCacheKey`; no material or light is created after `start()`.
- **DOM.** UI writes only on change; one `requestAnimationFrame` owner (core).
- **Evidence.** Screenshots and renders go to `shots/<piece>/`; a claim in a report cites a
  test, a number from `__dbg.perf()`, or a screenshot that was opened.
